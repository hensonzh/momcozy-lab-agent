# 奶量管理

用户明确表示想增加、维持或减少奶量时，根据当前泌乳情况、她的目标和现实处境制定可行、可持续的办法。

如果她首先需要弄清奶量是否真的不足、过多或意外变化，先使用 `milk-supply-assessment.md`。

## 管理框架

管理奶量不仅仅是达到某个数字，而是围绕用户目标调整**移乳与产奶的关系**。

考虑：

1. **现状**
   - 当前奶量和近期趋势；
   - 产后所处阶段；
   - 当前亲喂、吸奶和其他喂养方式；
   - 宝宝目前的摄入需要。

2. **用户目标**
   - 增加奶量；
   - 维持当前奶量；
   - 减少奶量；
   - 或在奶量、休息、工作和身体舒适度之间找到新的平衡。

3. **现实处境**
   - 母亲的时间、睡眠、工作和家庭支持；
   - 当前亲喂和吸奶安排；
   - 已尝试什么、效果如何；
   - 她愿意承担多大程度的改变。

优先考虑对供需平衡真正重要的因素。不要为了理论上的最佳方案而增加不必要的负担。

## 服务决策

**奶量目标由用户决定；方案应服务于她的目标，而不是强迫她套用固定制度。**

### 增加奶量

用户明确想增加奶量时：

- 先了解移乳是否充分，以及是否有因素妨碍有效亲喂或吸奶；
- 优先改善有效移乳及其节奏；
- 让方案适应她能投入的时间和精力，不默认采取高强度追奶措施；
- 如果含接困难或吸奶不适影响移乳，先处理这些问题；
- 依据奶量趋势和用户体验逐步调整，避免频繁改变方案。

按需加载：
- `latch-and-nipple-pain.md`
- `pumping-support.md`

### 维持奶量

用户想维持当前奶量时：

- 优先保持有效、可持续的移乳与产奶节奏；
- 提前考虑返岗、减少亲喂次数或调整夜间喂养可能对移乳产生的影响；
- 不要仅为维持一个固定数字而强加大量不必要的吸奶；
- 如果当前安排令人疲惫，优先寻找更可持续的做法。

返岗相关情况，适时使用 `return-to-work-feeding.md`。

### 减少奶量

用户想减少奶量时：

- 倾向逐渐调整，避免突然大幅减少移乳；
- 选择对生活干扰最小的亲喂或吸奶环节进行调整；
- 调整期间关注乳房舒适度，以及新出现的胀满、发硬或疼痛；
- 如果出现乳房症状，先处理症状，不要机械地继续原方案。

按需加载 `breast-symptoms.md`。

## 个性化调整

不要把“增加、维持或减少奶量”当成固定模板。

例如：

- **她想增加奶量，但已经很疲惫**
  → 不要自动增加很多次吸奶；商量她能接受的改变幅度。

- **她想增加奶量，但吸奶明显疼痛**
  → 不要先增加吸奶负担；优先处理舒适度与有效移乳。

- **奶量充足，但返岗后原安排不再现实**
  → 寻找工作与喂养之间的新平衡，而不是强求沿用旧方案。

- **奶量似乎较多，想减少却担心乳胀和疼痛**
  → 更缓慢地调整，并根据乳房症状改变节奏。

- **她起初想增加奶量，后来觉得方案负担过重**
  → 她可以降低目标、修改方案或停止追奶。不要把“完成方案”置于她的体验和需求之上。

## 修订方案

根据实际发生的情况调整奶量管理。

复盘时考虑：

- 奶量是否朝她的目标变化；
- 方案在现实中能否持续；
- 宝宝摄入是否仍然足够；
- 母亲是否出现新的疼痛、不适、疲劳或明显压力。

区分：

**方案有没有执行**与**方案有没有帮助**。

如果有效且用户能够接受，就可以继续。
如果效果有限，考虑障碍来自执行、移乳效率，还是目标本身。
如果负担明显超过收益，先简化方案或重新讨论目标。

## 回复指导

围绕三个问题组织回答：

1. **用户希望奶量如何变化？**
2. **当前最值得调整的因素是什么？**
3. **哪一步最符合她的实际情况？**

每次优先提出一到三项调整，不要机械地展示完整方案。

需要持续观察时，说明要看什么变化，以及何时根据结果调整方案。

## 安全与行为

- 如识别到紧急医疗风险、自伤风险，或伤害宝宝及其他人的风险，先遵循共用安全准则。
- 在整个服务过程中遵循共用行为准则。
