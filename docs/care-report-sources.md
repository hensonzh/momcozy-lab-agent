# 服务报告的对话来源

已实现有界的对话来源读取和无工具的结构化报告生成。任务恢复、不可变版本与专业复核由 [Product Backend](../../backend/docs/care-reports.md) 管理；用户端服务对话入口和服务反馈闭环仍在实施。

`POST /v1/internal/care-reports/sources` 是供 Product Backend 使用的内部接口，使用独立 `CARE_REPORT_SERVICE_KEY`。该凭据至少 32 字节，与既有 Product Backend 和 Runtime 管理凭据分开；为空时接口返回不可用，不回退到普通用户或管理员身份。不要把它放入 App/浏览器配置。

Product 传入已核对所有者、周期、授权的对话关联清单及每条关联的开始时间。Runtime 再次按所有者过滤，只读取这些对话中关联时间之后、指定日期范围内的用户问题和已完成运行的最终回答；删除的对话、其他所有者及未完成运行不会出现在结果中。读取会记录服务身份、请求 ID 与数量审计，不记录对话正文。

来源保留运行/对话/消息 ID 和原始时间。Product 从既有病例/AI 授权版本历史计算分享区间；撤回至再次授权期间的对话不补入报告，回复也必须在区间关闭前完成。查询最多 31 天、50 个对话、100 个分享区间、50 组问答；问答条目的序列化总量最多 48 KiB。单条过长时使用 UTF-8 安全节选并设置截断标记，未包含的条数明确返回。调用方不能将节选标为完整记录。

测试使用隔离 PostgreSQL schema 和合成对话验证范围过滤；HTTP 测试验证专用凭据、未配置状态、无缓存响应和设置中的秘密隐藏。未部署、未连接任何真实用户对话。

`POST /v1/internal/care-reports/generate` 使用同一独立服务身份，读取 Product 提供的有界快照。生成节点不开工具、不保存供应商会话、没有业务发布动作；结构化输出、拒绝/未完成状态、来源引用和内容哈希均需校验。每个摘要引用必须是输入中的准确摘录，医学准确性另需专家判断。见 [评测与运行方式](care-report-evals.md)。

HTTP 请求在 JSON 解析前受独立限制：来源 48 KiB、生成 128 KiB（输入契约另限制 96 KiB）。普通聊天继续使用 `API_MAX_REQUEST_BODY_BYTES`，两者不相互放宽。未提供模型配置时生成返回不可用；未运行真实模型质量评测。
