# 泌乳 Skill：渐进加载设计

当前维护入口为 `app/agent/skills/lactation/`：

- `SKILL.md` 只保存高频问题路由、共用工作方式、事实边界、安全边界和回复标准。
- `references/*.md` 保存各高频问题的完整评估与解决方案。
- 不建立内容版本目录；每个文档以自己的 SHA-256 指纹标识。历史 Run 保留加载当时的正文快照。

当前能力只提供咨询，不查询或写入业务记录。

## 高频问题与 reference

| 高频问题 | `reference_id` | 主要任务 |
| --- | --- | --- |
| 奶量、宝宝摄入、生长和混合喂养供需 | `milk-supply-assessment` | 分开判断生长、实际摄入和妈妈供需，保留未知亲喂量 |
| 泌乳建立、增加产出和可比产出下降 | `lactation-establishment-and-output-change` | 先保障宝宝摄入，再结合目标和现实约束选择低负担调整 |
| 含乳困难和亲喂乳头疼痛 | `latch-and-nipple-pain` | 区分含接、乳汁转移、损伤和求助信号，不远程确定病因 |
| 吸奶舒适度、适配和泵量变化 | `pumping-comfort-and-output` | 优先停止致痛操作，核对设备使用和可比条件 |
| 胀满、硬块、红热痛和炎症风险 | `breast-fullness-and-inflammatory-symptoms` | 避免过度刺激与创伤性处理，按症状变化及时转介 |

`SKILL.md` 不重复这些专题的完整步骤。模型确定主诉后只加载最相关的一个 reference；只有两个独立分支都会改变本轮行动时才加载第二个。

## 运行时流程

1. 系统提示词只暴露 `lactation` 的简短 manifest。
2. 需要泌乳专业规则时调用 `load_service_skill`，只传 `skill_id=lactation`，取得精简路由。
3. 根据路由再次调用同一工具，并传注册表中的 `reference_id`，取得一个专题方案。
4. 每次调用只在工具回执中返回资源身份与内容指纹；所选文档作为独立 `developer` 消息写入同一 Run。
5. 当前上下文已有相同资源和指纹时不重复加载。文档被历史压缩后只剩摘要，后续需要完整规则时重新加载。

工具不接受任意路径。reference 只从应用维护目录注册，文件名、frontmatter `name`、正整数 `order` 和非空 `description` 都必须通过校验。

## 内容边界

共同规则放在 `SKILL.md`，包括：先确认用户目标、一次只补最关键资料、区分用户报告与可核算事实、不虚构记录或执行能力，以及统一的紧急风险分流。

每份 reference 采用相同结构：

```text
# 适用问题
# 解决方案
# 复评与转介
# 依据与适用范围
```

具体数字、适用人群、设备限制和公开来源只放在相关 reference 中，避免无关问题加载全部专业正文。维护核对日期为 2026-09-23；公开资料整理和工程验证不代表已完成临床专家审核或真实模型临床验收。

## 验证边界

确定性测试覆盖路由体积、reference 注册顺序、Schema 枚举、未知 reference 拒绝、内容指纹、历史重放、同事务持久化及事件类型。`evals/behavior/v1/scenarios.json` 继续覆盖奶量、疼痛、风险、能力边界和多轮跟进；同一回合可以先后两次调用 `load_service_skill`，结构断言按工具名集合判断。

`--validate-only` 只校验评测目录，工程测试只验证加载与 Runtime 契约；二者都不等于真实模型已通过临床行为评估。发布前仍需运行真实回复评审，并对疼痛、炎症、新生儿摄入和生长风险场景进行专业抽检。多轮执行与发布门禁见 [对话与跟进评测](conversation-followup-evals.md)。
